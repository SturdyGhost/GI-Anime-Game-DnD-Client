## Ability-Entity Mapping Refactor

### Problem
Abilities were mapped to entities via `Active_Abilities.json` — a separate join table that had to be manually maintained alongside `.tres` ability files.

### Solution
Baked entity context directly into each ability `.tres` file with new fields:
- `entity_type` — "Character", "Companion", "Enemy"
- `entity_id` — FK to the entity
- `entity_name` — display name
- `weapon_type` — kit weapon type
- `ability_type` — "Basic Attack", "Charged Attack", "Skill", "Burst", "Passive"
- `kit_element` — which element kit (separate from `element` which is damage type)
- `active_ability_id` — preserved record ID for cooldown tracking

### Migration
- Ran migration script that read `Active_Abilities.json` and backfilled 542 `.tres` files
- 73 Sumeru enemy abilities inferred from filename patterns
- `GameDB.abilities_by_entity` index built during registration
- `Global.ACTIVE_ABILITIES` now builds from `.tres` fields with synced cooldown state merged on top
- New abilities only need the `.tres` file — no JSON editing required

## Enemy & Companion Passive Effect Registration

### Problem
Enemy and companion passive ability effects were never registered at battle start. Only player weapon/artifact effects were registered.

### Solution
Updated `Global.start_battle_effects()` to detect passives by:
- `ability_type == "Passive"` on the active abilities table
- `ability_type == "passive"` on the AbilityData resource
- `weight <= 0.0` on the AbilityData resource

This catches abilities like Ruin Grader's Iron Plating and Shock Absorbers, and Bennett's Benny's Luck.

## Battle Scene UI Improvements

### Ability Info Chips
When selecting an attack, chips appear below the dropdown showing:
- **Element chip**: "Applied: Nature" / "Applied: Physical" etc. with element-colored background
- **Stat chip**: "Roll: ATK" (physical) or "Roll: EM" (elemental)
- **Effect chips**: Any status effects, marks, or GameEffect descriptions

### Passive Filtering
Abilities with `weight <= 0.0`, `ability_type == "Passive"`, or zero-damage `targeting_type = "none"` are excluded from the attack dropdown.

### Enemy Cards
- Switched from `GridContainer` to `HFlowContainer` — cards wrap naturally based on available width
- After all cards render, widths normalize to the widest card
- Tier label on its own row below name
- Portrait: 180x180px, fonts scaled up (name 18, condition 18, tier 15, effects 15)
- Minimum heights on all text labels to prevent clipping

### Party Cards
- Portrait: 96x96px (from 52)
- Width: 264px with `SIZE_SHRINK_BEGIN` to prevent over-stretching
- HP bar: 14px height
- Element icon: 32x32
- Minimum heights on subtitle, effects, downed labels
- Companion portrait path fixed (directory typo "Portaits", filename format `ui-avataricon-{name}.png`)

### DM Hub Button
Purple "DM HUB" button in the action bar (DM only). Opens DMHub as a floating window without leaving the battle. Refreshes enemy/party cards on close.

### Unspent Points Banner
Gold banner below TopHotbar showing unspent skill/base points. Nearly opaque background, matches hotbar width. Dismissible via X button. Fixed: was being added to Node2D instead of the $UI Control node.
